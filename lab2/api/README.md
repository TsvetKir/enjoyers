# Учебный сервис api

Сервис для лабораторной работы № 2. Система мониторинга разворачивается отдельно в Kubernetes через Helm. Этот файл описывает только приложение, а не итоговый отчёт по лабораторной.

## Связь с первой лабораторной

Из `/Users/andrejfaddeev/enjoyers/lab1/api-service/main.go` перенесён обработчик `health` с исходным ответом `ok`. Сохранены подход с `net/http` и `http.ServeMux` и порт 8080. Вокруг обработчиков добавлен сбор метрик, JSON-журналы и OpenTelemetry. Это отдельная версия для второй работы; исходные файлы первой лабораторной не изменялись.

Обработчики `/eat` и `/burn` не перенесены: они удерживают выделенную память и создают бесконечную нагрузку CPU для опытов с cgroups. Для задания второй работы реализованы `/fail`, `/slow` и ограниченный пакет HTTP-запросов `/load`. Вместо немедленного `os.Exit` при SIGTERM сервер завершает текущие запросы и пытается отправить оставшиеся трассировки.

Dockerfile использует тот же принцип многоэтапной сборки, что `lab1/Dockerfile.multi`, с учётом новых зависимостей и запуска без root. Старый `prometheus.yml` собирает метрики cAdvisor, а не метрики приложения; конфигурация Compose из первой работы сюда не переносится, поскольку вторая работа требует Kubernetes и Helm.

## Обработчики

| Запрос | Поведение |
|---|---|
| `GET /health` | HTTP 200, тело `ok` |
| `GET /fail` | Намеренная ошибка HTTP 500; счётчик ошибок и span со статусом Error |
| `GET /slow` | Задержка 2 секунды внутри вложенного span `slow-op` |
| `GET /load` | 100 HTTP-запросов к собственному `/health`, 10 параллельных исполнителей; JSON с итогами |
| `GET /metrics` | Метрики Prometheus |

Одновременно допускается один пакет нагрузки; второй вызов `/load` получает 429. Вложенные запросы сохраняют контекст трассировки. Это учебная нагрузка, не нагрузочный тест производительности.

## Метрики и журналы

- `http_requests_total{method,route,status}` — число завершённых запросов.
- `http_errors_total{method,route}` — число завершённых запросов с кодом 5xx.
- `http_request_duration_seconds{method,route}` — гистограмма длительности в секундах.

Опрос `/metrics` не учитывается в этих метриках. Серии создаются после первого запроса к обработчику. Проверки `/health` учитываются; при построении графиков нужно осознанно выбирать фильтр по `route`.

Журналы HTTP-запросов записываются в stdout в JSON: `method`, `route`, `status`, `duration_seconds`, `trace_id`. Служебная запись о запуске не связана с запросом и не содержит `trace_id`. Ответы приложения содержат заголовок `X-Trace-ID`.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `HTTP_ADDR` | `:8080` | Адрес прослушивания |
| `OTEL_SERVICE_NAME` | `api` | Имя сервиса в трассировках |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | не задано | Базовый URL получателя OTLP/HTTP; библиотека добавляет `/v1/traces` |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | не задано | Полный URL для трассировок; имеет приоритет |

Используется OTLP **HTTP/protobuf**, обычно порт 4318, а не gRPC на 4317. Для незашифрованного подключения указывается схема `http://`. Фактический адрес получателя задаётся после установки Jaeger. Без адреса span и trace_id создаются, но трассировки никуда не отправляются. Для лабораторной сохраняются все трассировки.

## Проверка исходников

Требуется Go не ниже версии из `go.mod`.

```bash
go test -race -count=1 -v ./...
go build -o api .
```

Тест проверяет HTTP-ответы, задержку, пакет нагрузки, счётчики, JSON-журналы, связь trace_id, вложенный slow-op, статус Error и передачу контекста при внутренних HTTP-запросах. Тест не подтверждает установку или работу внешних Prometheus, Loki и Jaeger.

## Образ

```bash
docker build -t lab2-api:0.1.0 .
```

Dockerfile использует многоэтапную сборку. Итоговый образ содержит статический бинарный файл и сертификаты; процесс запускается с UID 65532 без прав root. Публикация образа и развёртывание через Helm выполняются отдельным этапом лабораторной.
